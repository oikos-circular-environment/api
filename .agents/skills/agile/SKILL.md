# Agile Software Engineering Workflow

## Filosofia de Colaboração

O objetivo deste workflow é alinhamento — chegar a um conjunto de decisões tomadas em conjunto, não entregáveis a serem produzidos rapidamente.

Sistema de valores:
- Perguntas são investimentos em correção, não sobrecarga
- Surfacear suposições cedo é barato; consertar trabalho errado é caro
- Acertar na primeira vez é mais rápido do que iterar sobre trabalho errado
- Múltiplas rodadas de clarificação são normais e encorajadas

## Fases do Workflow

### Fase 0 — Levantamento de Requisitos (00-start)

Leia o arquivo `.opencode/skills/agile/00-start.md` se existir, ou siga estas instruções:

1. Entenda a solicitação do usuário e use perguntas de entrevista para resolver requisitos ambíguos, preencher detalhes faltantes. Múltiplas rodadas de clarificação são esperadas.
2. Uma vez clarificado, apresente um resumo muito conciso dos requisitos acordados.
3. Sugira prosseguir para a Fase 1 (Epic Brief).

### Fase 1 — Epic Brief (01-epic-brief.md)

Leia o arquivo `.opencode/skills/agile/01-epic-brief.md` e siga as instruções para definir o problema e contexto.

### Fase 2 — Core Flows (02-core-flows.md)

Leia o arquivo `.opencode/skills/agile/02-core-flows.md` e siga as instruções para mapear fluxos do usuário.

### Fase 3 — PRD Validation (03-prd-validate.md)

Leia o arquivo `.opencode/skills/agile/03-prd-validate.md` e siga as instruções para validar requisitos de produto.

### Fase 4 — Tech Plan (04-tech-plan.md)

Leia o arquivo `.opencode/skills/agile/04-tech-plan.md` e siga as instruções para criar o plano técnico.

## Fluxo de Navegação

- Avance as fases sequencialmente, uma por vez
- Após concluir cada fase, pergunte ao usuário se deseja prosseguir para a próxima
- O usuário pode pular fases ou solicitar voltar a fases anteriores
- Mantenha o foco em alinhamento, não em velocidade
